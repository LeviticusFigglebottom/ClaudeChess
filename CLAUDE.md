## Invariants — violating any of these is a bug

1. **POV normalization happens exactly once.** Raw `EngineInfo` (and everything in `src/lib/engine`) speaks side-to-move POV, as UCI does. `src/lib/eval/pov.ts` is the only conversion point to White-POV. Never add a compensating negation anywhere else. DB stores White-POV cp/mate; win probabilities are mover-POV.
2. **UCI strings never leave `src/lib/engine`.** The rest of the app talks to `EngineClient` (spec §3.2) only. This now includes test tooling: the Node cross-check harness lives at `src/lib/engine/node-engine.ts` (child-process CLI mode; never import from app code).
3. **chessops never leaves `src/lib/chess/position.ts`.** The facade is the single home of Result handling and Move/Square encodings; everything else consumes plain strings. Castling conventions are fixed there: internal king-takes-rook; standard emits classic UCI (e1g1) and accepts both encodings; **chess960 FENs always serialize castling as X-FEN file letters (HAha), never KQkq**.
4. **Every analysis, classification, and trainer query filters on `variant`** (A1.4). A 960 blunder and a standard blunder are different populations — never pooled. `BOOK` fires only for `variant === 'standard'` (enforced in classify.ts); §9.4 repertoire and A3.4 opening matching are standard-only.
5. **The engine refuses variants it cannot evaluate.** Vanilla Stockfish serves standard/chess960 (`UCI_Chess960` at init — an engine-instance option, not per-position); the vendored Fairy-Stockfish build (`public/engine/fairy/`) serves threecheck/koth (Phase 4.5, `FAIRY_ENGINE_VARIANTS`); crazyhouse still throws (no drop UI — B1.1). Standard/960 must NEVER route to Fairy (weaker there). A meaningless eval silently corrupts every trainer (A1.3).
6. **Never classify on raw centipawns** — convert through `winProb` first (spec §4.1). Thresholds live in `src/lib/eval/classify.ts`, pinned by tests.
7. **Trainer flags (spec §9), amended by owner directive 2026-08-22:** the five analysis-derived trainers DEFAULT ON (they never touch live play); env `NEXT_PUBLIC_FF_*=0` is a deployment kill switch; FF_VARIANTS/FF_MAIA keep default-off. `src/lib/flags`.
8. **Cross-origin isolation must hold** (`next.config.ts` COOP/COEP). Any new external resource must be self-hosted or proxied. If `/engine-check` shows red on a deploy, fix that before feature work.
9. **Glicko-2 updates are batched per rating period** (12 games / 7 days), never per game (spec §7).
10. **Rating pools never blend** (Phase 2): GAMBIT's Glicko lives on the Stockfish UCI_Elo scale (that's what the bots are calibrated against); imported chess.com and Lichess ratings are two *other* pools. Any UI showing more than one labels each with its pool — never average, compare, or convert between them.
10. **Engine binaries are vendored** (`public/engine/`, committed). No build or install step may fetch them (A0.1). GPL notices: `NOTICE` + `/licenses` — update both when engine or rules deps change.
11. **Account conversion links, never copies** (A2.1): the Supabase auth id IS the users.id, so anonymous→permanent must only flip flags on the same row. Any code path that creates a second user row or rewrites child FKs during conversion is a bug (pinned by `src/lib/account/account.test.ts`).
12. **Every LLM and analysis route consumes through `src/lib/account/usage.ts`** (A2.4): `consumeUsage` before/after paid work, or `checkUsage` + the `guarded-stub` chain (401 → 403 unverified → 429 capped) for routes whose bodies haven't landed. `/api/import`, `/api/analyze`, `/api/coach`, `/api/classify-blunder` all carry the guards ahead of their real bodies (guards were never loosened when the 501 stubs were replaced); LLM routes consume a unit only on real model calls — cache hits are free. Anonymous caps are all zero; client-side engine use is deliberately unmetered.
13. **Account domain logic lives in `src/lib/account/*` and takes a `Db` handle** — no HTTP, no Supabase, no `next/server` imports (api.ts and guarded-stub.ts are the only route-facing adapters, and stay out of `index.ts`). This is what lets the whole account system be tested against in-process PGlite (`test-db.ts` applies the real migration chain).
14. **Supabase env is optional**: absent → the app runs local-only (localStorage prefs/ratings, no persistence, "local mode" chip); present → anonymous session on first visit (A2.1). Nothing may hard-require an account service to play, do puzzles, or analyze locally. Server rating state is authoritative once a session exists — it runs the same `src/lib/rating/period.ts` the client runs, and client caches are overwritten by server responses.
15. **Motif detection is deterministic code, never a model** (C0/C2/C5): detectors in `src/lib/motifs/detect.ts` are pure predicates over stored analysis; every fixture in `src/lib/motifs/fixtures.json` must return its expected motif at rank 1 (a miss is a bug with a repro, not a statistic). The LLM only writes prose over proven evidence (`/api/classify-blunder` explanations, cached by `(motifChain, evidenceHash)`) or judges free-prose input (`/api/coach`, §9.5) — it can be wrong about wording, never about chess. Everything in `src/lib/llm` is server-side; the model id is spec-pinned in `client.ts`.
16. **The server is authoritative on live games** (Phase 4): every action replays through the facade inside an advisory-lock transaction (`withGame`); premoves get FULL validation (A3.5); clocks are charged by `src/lib/clock/clock.ts` and flag claims are verified server-side, with the SIGNED remaining (`remainingRawMs`) recorded in the end event — the Phase 4 drift evidence. State reads lazily finalize flagged games so a stalled client can never wedge one. The Realtime channel carries a seq-only poke; nothing trusts channel payloads. **A3.6 drift bound (amended on derivation, deployment pass 2026-08-22): |remainingRawMs| ≤ serverRoundTripP50 + 150ms — NOT a fixed 200ms.** Finalization happens on the first state read past zero, so drift can never be smaller than one round-trip; a fixed 200ms is arithmetically unreachable at a ~312ms RTT (measured −366ms vs a 464ms bound on real Vercel+Supabase; the in-container −41ms was a loopback artifact). Do not re-tighten to the old number: the mechanism (never finalize early, signed evidence) is the guarantee, the bound is a function of read latency.
17. **Trainer flags resolve env OR per-user prefs.labs** (`useFlag`) — overrides can only turn features ON. Trainer reports all filter on one `variant` (invariant 4 applies to §9 too; `calibration_attempts.variant` exists for exactly this).
18. **Every pool search runs under the §3.3 watchdog** (from the calibration session's 2.5h wedged-search incident): budgets are FITTED per (depth, MultiPV) from measured p99 (`src/lib/analysis/budgets.ts`, re-fit with `scripts/fit-search-budgets.mts` — never guessed constants); breach → `stop`; `stop` ignored → the child is KILLED and the pool replaces it; ladder retries at reduced MultiPV then reduced depth; final failure marks the ply `degraded` (with `analyzedAtDepth` = depth actually reached and the reason recorded) and the batch CONTINUES — a hung engine can never hang an import. Degraded plies are excluded from every §9 statistic and render as "incomplete" in review, never silently wrong. A worker that soft-breaches three times in a session is retired. Synthetic-hang coverage: `src/lib/engine/watchdog.test.ts` (mock UCI children that wedge / honor stop late / behave). The verify pass's shape is **24:1** (MultiPV 1, fitted 64s — measured, not extrapolated from 24:3); the 524 plies the old 20s soft-stop had touched were re-verified under the honest budget (121 flips, near-symmetric, 0 degraded — `scripts/reverify-d24.mts`), and a degraded verify search never overwrites complete lower-depth numbers (guard in `verifyBorderline`).
19. **Explorer data is layered local-first** (Task 2b): §9.4 repertoire and §9.1 empirical read the SELF-HOSTED aggregate (`explorer_agg`, seeded from the committed `src/db/seed/explorer-agg.jsonl.gz` — built offline by `scripts/build-explorer-agg.mts` from a Lichess monthly dump, first 16 plies, band = EXPLORER_RATINGS floor of avg elo, pruned) with the live explorer as enrichment only, never a requirement. The interactive panels fetch `explorer.lichess.ovh` CLIENT-SIDE first (residential IPs pass; the datacenter 401 doesn't apply; measured on the deployment: COEP require-corp does NOT block the CORS fetch) with the server proxy as fallback. Aggregate and live API share one contract (band/speed labels, `ExplorerPosition` shape) so sources sum interchangeably.
20. **Serverless engine spawning has two hard requirements** (measured on prod 2026-08-22 — every /api/analyze call burned the full 300s FUNCTION_INVOCATION_TIMEOUT): (a) the vendored engine files MUST be traced into the function bundle via `outputFileTracingIncludes` in next.config.ts — `public/` deploys to the CDN, NOT the function filesystem, and a runtime-computed spawn path is invisible to static tracing; (b) `ServerEngine` fails FAST — child exit/error rejects every pending wait with the captured stderr tail, and init itself has a 20s deadline — so a dead child costs seconds and a diagnosable error, never a hung request. `/api/analyze` declares `maxDuration = 300` and sizes chunks (60s work target) so the worst single-search overshoot (64s verify search) still fits; the client has a stall guard and shows the verify phase. **Batch analysis is CLIENT-FIRST (§3.3 revision, owner-directed):** capability detection (`crossOriginIsolated && cores ≥ 4` + engine-boot timeout) routes review analysis to the browser engine (`src/lib/analysis/client-batch.ts`, threads cores−1≤8 — deliberately independent of the calibration-pinned interactive `defaultThreads`), streaming per-position to `/api/analyze/ingest`, which derives EVERYTHING through the same code as the server path (`positionEvalFromInfos` → `writePlyRecord`/`applyVerifyPair`); the server chunk loop is the fallback. Progressive depth 12→18→24-verify: `analyzedAtDepth < 18` = provisional — visibly marked, excluded from §9 stats and accuracy (gates in every trainer query), refused by `needsVerify`, treated as unanalyzed by the server path; depth only moves a row UP on ingest. Measured (75-ply game, 4-core container): first useful review 12.5–19.7s, d18 sweep 2.6s/position vs 4.4 serverless.
20. **Calibration fit invariant (from the 2000-band blowout):** the measured-strength curve is only invertible within a shared search *shape*, and shape means **truth depth AND MultiPV together** — MultiPV varies per band (§6a), so cross-band inversion inside a depth segment is still cross-shape. Cross-band fits produce first proposals only; every band's params must pass its own-shape 20-game checkpoint (nominal inside the 95% CI) before finals count. **No interpolation anywhere in d18 — option (c) is closed permanently.** Also: SF18-Lite's UCI_Elo **1400 label is defective at 400ms** (~160 Elo weak, three-way corroborated — `data/calibration/ruler-checks.txt`); never anchor on SF@1400 — band 1400 anchors on SF@1320.

Home (`/`) is auth-switched: marketing for guests/anonymous, the daily-review dashboard (sync→analyze chain, fingerprint, drill-of-day, latest game) for signed-in non-anonymous users — under dev-auth every visitor looks signed-in, so the marketing branch is only observable in prod or env-less mode.
- **Remote-container constraint (measured 2026-08-22):** the remote session's container freezes within minutes of the session going idle, and background process trees can be killed by worker restarts — long arena runs only progress while the session holds active foreground waits (sanctioned `until …; do sleep 30; done` loops; bare leading `sleep` is blocked). The arena checkpoints every game (JSONL append) and resumes from the shard's line count, so an interruption costs only the in-flight games. **Wait-loop trap:** `until ! pgrep -f <name>` inside a Bash tool call matches the wrapper's OWN command text (the harness embeds it in a `bash -c` eval) — the loop never exits and, worse, reads as "still running" forever. Write a pidfile at launch and poll `kill -0 $(cat pidfile)` instead.
